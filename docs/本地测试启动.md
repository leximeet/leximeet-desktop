# 本地启动与隔离验收

## 获取源码

GitHub 与 Gitee 平级，任选其一；不要在同一个目录重复克隆：

```bash
# GitHub
git clone --recurse-submodules https://github.com/leximeet/leximeet-desktop.git
# 或 Gitee
git clone --recurse-submodules https://gitee.com/leximeet/leximeet-desktop.git
```

`core-java` 固定到 gitlink 指定的提交；相对地址 `../leximeet-desktop-core.git` 跟随主仓默认远端解析，不能用 Core 最新 main 替代。已有检出更新配置后运行 `git submodule sync -- core-java`，再运行 `git submodule update --init core-java`。Fork 仓库若没有同组织 Core，可先执行 `git submodule init core-java`，再用 `git config submodule.core-java.url <官方 Core 仓库地址>` 覆盖本地下载地址，最后执行 update；后续 sync 会重置这项覆盖。

两端下载服务各自可用与否不影响源码地位。当前词典下载脚本仍使用已锁定的 GitHub Dictionary 0.0.3 Release 地址；可通过脚本支持的本地资源目录准备同摘要词包，不自动改写下载地址或校验值。

## 一条命令拉起新装体验

在 Desktop 仓库目录执行：

```bash
bash scripts/test-desktop.sh
```

脚本优先使用已安装的 Node.js 24+、JDK 21、Maven 3.9；没有可用环境时，将官方 Node 24.14.0、Temurin JDK 21、Maven 3.9.11 下载到 .runtime/tools 并校验，不修改系统 Java。macOS / Linux arm64、x64 已有自动准备环境的分支，本轮实际验证的平台是 macOS arm64。Windows 需要自行准备环境，本轮不宣称 Windows 已通过验收。

脚本还会安装锁定依赖、校验 Electron 44.3.0、准备 Core Text、构建当前前端 / Core，再启动可见窗口。macOS 会先构建本地 ad-hoc 签名的 `LexiMeet Acceptance.app`（bundle ID `org.leximeet.desktop.acceptance`），使用独立通知身份；首次打包需要额外时间，应用在本轮会话的 `applications/<构建时间>` 子目录，不覆盖旧候选。这不是 Developer ID 公证发布。默认每次独立 UUID 资料目录；没有示例词条、遇见或学习成果，首启先显示进入 / 跳过教学邀请。已有的正确系统下载缓存仅以只读方式复用；项目缓存和验收资料留在 .runtime。

首次依赖、工具下载需要网络；词典优先使用已核验的相邻 Dictionary dist/v0.0.3，否则下载固定官方 release。安装后的文本功能离线使用。下载失败尝试当前网络及本机 7897 / 12334 代理；仍失败会明确报错，不跳过校验。Core 子模块需要已初始化：完整检出时使用 git clone --recurse-submodules，已有缺失检出先 git submodule update --init core-java。

## 继续同一空间与检查环境

终端会显示空间 ID、资料、启动日志和实际工具路径。

```bash
bash scripts/test-desktop.sh --resume <空间ID>
bash scripts/test-desktop.sh --check
```

--check 只读检查环境和固定物料，不下载/安装/编译或创建资料；缺项会明确报错，正常启动自动准备。

resume 不创建新资料，适合检查重启后的恢复。默认再次运行会创建全新安装空间，也可使用 --fresh。根据设置，关闭窗口后应用可能仍在运行；请先从菜单选择“退出词遇”完整退出，再 resume。同一空间仍在运行时，会拒绝重复启动。

业务文件在 .runtime/desktop-sessions/<ID>/core，Electron / 音频设置与缓存也在该空间。日志在 logs/launch.log，acceptance.json 保存环境、进程与退出信息。脚本不注册浏览器 Native Host，不访问日常浏览器资料，不默认读系统剪贴板或设置开机启动。需要剪贴板测试时在当前独立应用设置里主动开启；退出后自己的快捷键与监听会结束。

## 后台自动门禁

```bash
bash scripts/test-background.sh
bash scripts/test-desktop.sh --journey
```

第一条命令依次准备当前源码、运行 Desktop 单元、Core 测试、真实 Java 进程 / HTTP 集成、原生 Electron E2E 和 UI；第二条专门模拟首启与七天日常使用，推进独立业务时钟，不改系统时间。实际双包升级参数见[日常使用与升级测试](日常使用与升级测试.md)。本机测试按例创建独立目录、动态端口和隐藏不可聚焦窗口，不污染手工验收空间；清理只针对自己持有的资源。后台入口降低进程优先级、限制并发并默认静音；macOS 另通过只读 AppKit 工具监测启动前到退出后的系统激活，需要 Xcode Command Line Tools。工具缺失或监测不完整明确失败，详情与报告见[后台自动化测试](测试与CI.md)。原 `bash scripts/test-desktop.sh --verify` 仍兼容。

有现成 Node 24+ / JDK 21 / Maven 3.9 环境时也可以执行下方命令。直接使用 npm 不会替你切换 Java；本机默认 JAVA_HOME 指向其他版本时，请使用上面的脚本，或在当前终端指定自己安装的 JDK 21：

```bash
export JAVA_HOME="/path/to/jdk-21"
export PATH="$JAVA_HOME/bin:$PATH"
```

然后执行：

```bash
npm run verify:desktop
npm run test:desktop
npm run test:package:desktop
```

最后一项需要先生成应用包：

```bash
npm run package:dir
```

打包要求与当前 OS / CPU 匹配的 JDK 21，随包 Java 由 jlink 裁剪。当前构建包含固定脚本与随包 Native Host，打包无需系统 Node / JDK；构建和测试不会注册到日常浏览器。package 套件在测试进程中模拟主机 Java 不可用，检查应用是否遗漏随包运行时，避免开发机环境掩盖问题。原生报告在 playwright-report/desktop-001，应用包报告在 playwright-report/desktop-001-package；JSON 与截图在 test-results/desktop-001。

当前连接验证入口：

```bash
npm run verify:lmcp:contract
npm run test:lmcp:transport
npm run test:connected
```

依次验证固定物料、真实 Native Host/UDS 与 Java、原样 Browser 生产联调。最新逐层结果见[1.0.0 验收](测试与CI.md)，不沿用历史 0.0.1 数量。旧 Connector/Java Native Host/首次接管测试已移除，不再要求 63 方法或合并协议。

一键拉起随包桌面 + 专属 Chromium：

```bash
bash scripts/test-desktop.sh --connected
bash scripts/test-desktop.sh --connected --check
```

脚本自动准备 Node/JDK/Maven/依赖和 Chromium，运行时使用随包 JRE/外置 Host。每轮新建的业务空间、应用包和浏览器都放在专属系统临时目录中，具体位置由终端输出，避免浏览器读取桌面受保护目录时被 macOS 拒绝；不会注册到日常 Chrome。用户完成配对后，可通过终端 stop/restart 验证本轮的临时失联与恢复，期间保留本轮数据。按 Ctrl+C 或关闭验收浏览器后，脚本会结束自有进程、撤销注册，并回收本轮应用、浏览器与业务资料副本，只保留小型日志和 acceptance.json，避免反复验收占用大量磁盘。实际包的摘要在退出前记录。该双端入口不提供跨候选 --resume，步骤和平台限制见[双端隔离验收](插件连接.md)。

启动失败或 Worker 异常退出时保留诊断环境。检查后使用终端显示的完整会话 UUID 定向回收：

```bash
bash scripts/test-desktop.sh --connected --cleanup <会话UUID>
```

此命令不启动或构建项目，仅接受一个会话 ID；仍有进程、未撤销 Native 注册、记录不一致或目标是软链接时会拒绝。不会删除其他会话、日常应用或从外部提供的应用包。独立 Desktop 的 `--resume` 空间仍按原规则保留，不受双端环境回收影响。

双端人工启动完成后，浏览器默认选中包内使用教学，并另留 Node.js 英文文档供阅读验收；外网访问失败自动回到本轮本地英文页，不关闭浏览器。后台自动联调始终使用本地英文 fixture，不依赖 Node.js 网络可用性。浮球在侧栏打开时仍保留，右键可打开或收起原生侧栏。

## 建议人工验收顺序

1. 新空间首启选择进入或跳过，进入后先介绍侧边栏。目标默认雅思，可改选或暂不设置；计划也可暂不设置。发音自然结束才庆祝；设置无需操作也能下一步，采集开关允许自选。「设置 → 使用教学」可继续或重开邀请。
2. 学习规划使用两步弹窗：选择目标 → 每日新学 / 复习、提醒与预览 → 保存。先试回退 / 取消，确认当前规划不变，再保存；默认新学 10、复习 20。调整计划保留目标；提醒默认 08:00–20:00，关闭后隐藏范围。无规划也能记录和自由练习。详见[学习规划](学习与复习.md)。
3. 六种模式顺序为列表、看词选义、临摹、默写、听音辨词、语境填空。列表默认遮挡中文，一键遮挡英文；熟练 +1 / 不熟悉 −1 不直接改成掌握。其余输入自动校验并计算熟悉度；使用提示与临摹不会冒充独立回忆。输入部分答案后退出，再 resume 检查位置和草稿。
4. 在本次隔离应用开启剪贴板识别：没设目标时复制英文应静默。设定一本文本词书，从目标列表选两个词，加一个目标外词组成文本；只通知两个目标词。分别接受 / 拒绝，10 秒后按偏好保存命中词所在的安全句子并关闭。默认七天内重复语境不再提醒或保存；可用自编的假邮箱/密码检查 `xxx` 脱敏，勿输入真实秘密。也可明确选「整本词典」后复制 `alpha beta gamma` 检查逐词通知。再检查关闭默认采集后的超时拒绝、切换目标立即撤回，以及暂停计划仍可采集目标语境。系统通知权限不足时应显示错误、不采集、不弹替代窗；可明确改选独立弹窗；测试结束关闭识别。详见[采集方式与语境](采集与隐私.md)。
5. 快速记录或遇见采集快捷键打开独立编辑器；收起后草稿仍在，保存才产生记录。词卡笔记、多词本归类和回收站在正常使用时操作，不加入教学。
6. 词库中心补到真实 Full，可取消、完成并回退。增量资源约 45.31 MB，索引构建另需磁盘空间。
7. 默认有道播放，再选微软或自定义 GET / POST；失败应可见。设置本机数据能打开目录，本版不提供导入导出。

### 阅读与练习回归检查

- 在「我的词库」选词，查看语境 / 释义 / 记录，点击铅笔编辑；输入笔记后切词、切页或收起词卡，再返回检查草稿。
- 搜索不存在的单词，右侧不应保留旧词或保存按钮；清空搜索后可以重新选择。缩到 1000px / 820px 时词卡排到列表下面，文字和控件可以滚动访问。
- 在列表的第二行点「熟练 +1」，再切换临摹，应恢复临摹模式自己的位置；回到列表后，原行反馈和列表位置仍保留。临摹 / 默写拼对后直接记录，保存确认后稳定显示 1 秒再自动下一词；期间快速点击或 Enter 不会重复加分或提前切题。可在「练习设置」关闭自动切题，改为 Enter /「熟记」继续。临摹首次正确 +1、默写 +2；未输入字母只显示淡色幽灵提示。
- 创建单词本弹出对话框，Esc 退出不创建；批量加入单词本可以多选，回收须二次确认；对话框打开时主页面快捷键不可穿透。发音设置未保存时切到主页面再回来，输入仍保留。

### 系统通知验收边界

原生自动化替换系统剪贴板输入与 Notification 投递，仍运行真实 Main、计时器、独立窗口与 Java/SQLite，用于验证逐词事务，不影响操作者剪贴板和系统通知。OS banner、通知权限和快捷键占用需在上面的独立验收应用手工检查；Electron show 回执不能证明屏幕实际出现 banner。Electron 42+ 的 macOS 原生通知要求签名应用，见 [Electron 官方说明](https://www.electronjs.org/docs/latest/api/notification)。首次请在系统提示中允许 `LexiMeet Acceptance` 通知，或通过采集设置中的按钮打开系统通知设置；脚本不代替用户授权。未收到系统 show 回执不会开始自动采集；明确选择弹窗模式时，窗口就绪后才计时。

## 窗口内快捷操作

⌘ / Ctrl K 搜索整个词典，⌘ / Ctrl , 打开设置，⌘ / Ctrl 1–7 按导航顺序切换页面。我的词库列表聚焦后 ↑ / ↓ 切换词条；笔记草稿在本窗口的页面切换时保留。设置按用途分栏，切分栏不会清空尚未保存的发音输入。详见[界面与引导](界面与交互.md)和[当前视觉验收](界面与交互.md)。

## 插件连接

「设置 → 插件连接」自动检测插件，一键发起连接并等待浏览器确认；也可断开连接与撤销授权。隔离双端启动已注册本次浏览器，无需再次注册。插件 A 本机封存、桌面 B 不变；采集 C 到桌面，断开恢复 A，桌面 B+C。临时断线不切独立、不新增到 A。

导航等待主 Renderer 接受路由后返回 opened；路由接受与系统是否允许窗口聚焦分别判断。只支持词库/规划/设置/指定词。记录结果未知时，保留原 mutationId 并查询回执，不能自动换 ID 再次采集。管理与学习在桌面完成；本轮 browser/1 反向网页能力只提供可选框架，不能据此宣称生产网页操作已通过验收。[插件连接](插件连接.md)提供完整契约说明。

## 其他开发入口

npm run preview 提供真实 Core 的浏览器预览，使用独立临时资料；它只用于视觉检查，不能替代原生 IPC / safeStorage / 窗口验收。设计参考的有效交互已归并到界面文档，不作为正式应用的数据源。

npm start 指向正式本机库；不要用它进行隔离验收。dev 是持久开发空间，排查首次安装或缓存问题请使用上面的新 UUID 空间。

### 临摹教学与规划回归

- 完成临摹后重新开始教学，应能再次输入，不因上次只读完成状态卡关。
- 临摹中输入部分字母、退格、切走再返回；完整草稿在自动提交前退出后可续接。中文输入法组词有可见提示，确认候选使用的 Enter 不应提交半个词。
- 规划弹窗宽窗/窄窗都有可访问的保存按钮；教学右侧或下方讲解不覆盖表单。取消后无目标或配额变更；修改每天复习为 0 后关闭并续用同一资料，值应保留。

## 本轮学习规则验收

使用全新隔离空间验证初始 10、首次 20、满分 30 与通知模式，再通过 `--resume` 验证同模型重启。当前个人数据库直接初始化 schema 100，不转换旧测试库；旧 / 未知格式拒绝并保留，不能要求应用自动清空或检查旧迁移确认页。默认不访问正式资料。通知单题人工流程见[系统通知练习](学习与复习.md)。时间衰减由固定时钟自动测试覆盖，不要修改电脑系统日期来验收。

学习提醒：规划中只设置提醒开关和时间范围；进入「设置 → 学习提醒」选择通知题型。默认约 30 分钟随机提醒，不需要选择间隔，无每天 3 次上限。测试提醒时须有任务、后台运行且通知获系统许可；先等 25–35 分钟，休眠错过不追补。调度自动测试使用可控时钟，不需要真实等待半小时。

普通桌面 Core 的启动握手最多等待 45 秒，覆盖首次 Java 类加载和原生库解压；实际启动就绪即继续，不强制等待满期限。JDK 不匹配或进程退出仍立即报告。隔离测试使用 JDK 21，并给整体装配留出有界等待预算，不自动重试。

## 回收可重建包

```bash
npm run prune:artifacts -- --dry-run
npm run prune:artifacts
```

先预览，再清理已结束验收的包副本。脚本拒绝符号链接和运行锁，保留用户资料、日志、证据与依赖缓存；不会清空整个 `.runtime`。隔离资料清理需核对其 test/demo 标记与所属进程已退出，未知资料保留。
