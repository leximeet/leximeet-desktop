# 依赖、源码与安装物范围

本页说明自有业务源码、外部运行库、数据素材与冻结规范各自的范围，以及当前入口和打包结构。不能根据目录名判断代码是否原创，也不能把许可证文件当作可随意删除的缓存。

## 正式入口

前端入口为 `frontend/index.html → frontend/src/main.js → App.vue`。主窗口装载 `desktop/DesktopShell.vue`，独立采集窗口装载 `desktop/CaptureWindow.vue`。正式学习、词库、规划和设置页面位于 `frontend/src/desktop`。

`frontend/src/components` 只保留正式使用的 `Icon.vue` 和 `CardLayoutSettings.vue`。16 个未引用旧页面、7 个旧辅助库及对应的五份模型测试已经退休；当前全部 54 个 Vue/JS/CSS 文件均由正式入口到达。入口闭包测试同时核对 Main、preload 与 Renderer 的命名业务合同，避免旧接口只在某一层遗留。

旧页面的静态 Renderer 替身、像素基线和旧学习模型 Electron 用例也已移除。当前原生 UI 在 `tests/desktop001`；设置提交顺序、迟到响应、布局与持久化的有效断言由当前源码测试维护。

不能据此删除整个 `components`、`lib` 或 Electron/Core 目录。主进程还有词典 Worker、preload、Egg 配置、Native Host 等运行入口；Core 用显式装配建立服务，目录是否叫“旧”不决定其是否运行。

## 单一词典与已退休实验链

当前正式词典是 LexiMeet Dictionary 0.0.3，经 `TextDictionaryService`、Worker 和 Core 的只读公共索引装配。旧 `resources/dictionaries/ecdict`、同步 `Dictionary`、ZIP 内容包服务、导入工具及旧来源账本已经移除，启动不再读取旧 manifest。

Renderer / preload / Main 同时关闭旧 `lookup`、`translate`、翻译缓存、`todayQueue`、质量指标和 CSV vocabulary 动作。当前查词走 `dictionaryAction`；规划、练习、队列和采集走 `desktopState` / `desktopQuery` / `desktopCommand`。内容包导入与回退不再是隐藏原生操作。

旧翻译适配器的 TranslationPlugin notice 随其完整退休一同移除；当前 Edge **发音**是另一条仍在使用的服务，不能连带删除其依赖或来源记录。`ws` 和 `https-proxy-agent` 仍处理真实发音连接与代理。

新词典的 `resources/dictionary/notice-ECDICT-LICENSE.txt` 继续保留：Dictionary 0.0.3 聚合了 ECDICT 数据。聚合词典自己的来源锁、数据 notice 与 LMCP 快照均不属于旧链清理范围。

## LMCP 是什么引用方式

`core-java` 是 Git 子模块；`resources/lmcp` 是普通跟踪文件组成的固定规范快照，不是子模块或外部 SDK。`source.json` 记录协议仓提交、版本、摘要；构建工具核验 17 个规范文件。

Desktop 快照用于构建核验、随包物料核对和接入文档。Core 在 Jar 内另外保留 `/lmcp/` 快照，启动和请求校验会读取它。运行时不访问相邻协议仓，也不在线下载 Schema。

协议仓可以独立维护和发布。消费端固定到已验证版本；插件的宿主扩展可以灵活适配，共同消息、授权和错误约束仍须一致。整个 Desktop 快照约 0.32 MB，不是缩包目标。

## 自有源码与其他必需文件

当前业务源码主要在：

- `frontend/src/desktop`、`main.js`、`App.vue`、两个共享组件，以及 `lib/api.js`、`card-layout.js`、`practice-audio.js`、`readable-markdown.js`。
- `electron`：主进程、IPC、系统能力、Worker 和 `electron/native-host/main.cjs` 自有连接桥。
- Core 的 `src/main/java`：领域服务、SQLite 事务、练习、查询、复习调度适配与 LMCP。

完整软件还需要 `frontend/index.html`、Core `src/main/resources/domain` 与 `lmcp`、词典、图标、许可和构建配置。`scripts` 中的 Java、词典、JRE、Native Host 和打包准备工具是自有构建源码，不应全部误判为测试或第三方库。

测试、`node_modules`、`target`、`frontend/dist`、`.runtime` 和 `release` 分别是验证、外部依赖或产物。源码归档应保留构建方法与测试，业务代码摘录的范围可以更窄；不能为了摘录材料而破坏完整对应源码。

## 安装包为何大

`package.json` 分两层打包：业务前端、Main 与生产 npm 依赖进入 ASAR；Jar、裁剪 JRE、词典和 Native Host 进入额外资源。ASAR 是不做压缩的归档，DMG / ZIP 是压缩分发物，展开应用和下载文件大小不能混算。[ASAR 官方说明](https://github.com/electron/asar)、[electron-builder 文件收集说明](https://github.com/electron-userland/electron-builder/blob/master/website/docs/contents.md)。

2026-10-04 的 1.0.0 / macOS arm64 候选（Desktop `e9e38369`、Core `8603bf2c`）展开应用约 **907.8 MB**，DMG **581.9 MB**，ZIP **580.4 MB**。以下采用不重复计入符号链接的实际文件字节，十进制 MB；磁盘块、APFS 克隆和 Finder 显示可能不同：

| 部分                      | 实测 MB |
| ------------------------- | ------: |
| Electron 框架             |   298.7 |
| Dictionary SQLite         |   386.5 |
| Dictionary 压缩源及元数据 |    96.7 |
| 裁剪 Java 21.0.9 运行时   |    53.4 |
| Core Jar 与许可           |    24.6 |
| ASAR                      |    26.5 |
| Electron 许可             |    20.1 |

清理前展开应用约 943 MB、ASAR 约 51.1 MB；旧 ECDICT 约 24.35 MB 已删除。新包未包含 Full 或离线音频，Dictionary Core Text 117,902 条；完整度由随包文件检查和真实安装测试证明。生产 npm 依赖属于 SDK，不计作自有业务源码。Java 使用 [JDK 21 jlink](https://docs.oracle.com/en/java/javase/21/docs/specs/man/jlink.html) 加入需要的模块并压缩、去调试信息，不携带整个 JDK 的编译工具。不同时间、词典配置及 Java 版本的旧文件不能混作本轮体积基线。

随包同时保存预生成 SQLite 和压缩源，目的是快速离线启动及后续复用原资源。首次还把索引复制到个人空间，因此展开包占用与首次运行后的总磁盘占用是两个指标。

可选的词典主载体设计：

| 方式                          | 展开安装体的变化 | 代价                                             |
| ----------------------------- | ---------------- | ------------------------------------------------ |
| 现行 SQLite + 压缩源          | 保持现状         | 体积大，离线首启快且能复用源                     |
| 仅压缩源，首次本机建索引      | 减少约 386.5 MB  | 增加首次初始化等待，需进度、取消、重试与磁盘检查 |
| 仅 SQLite，需要升级时补下载源 | 减少约 96.6 MB   | 首启仍快，离线重建和增量复用流程需调整           |
| 安装后下载词典                | 减少约 483.2 MB  | 首次使用需要网络，改变现行离线体验               |

这些方案尚未实施，不能只删除一个文件就宣称优化完成。如果优先缩小安装体，可以考虑只保留压缩源；如果优先保证首启速度，则可保留 SQLite。直接以只读方式挂载随包索引，还可减少个人空间中的重复拷贝，但不会缩小安装体，且必须验证应用移动、升级与回退。

当前索引没有 SQLite 空闲页；仅 VACUUM 不会减少一半。公共词条样本从 deflate level 1 改到 6 / 9，只减少约 4.5% 的 payload；整体收益约十 MB 量级。改为块压缩和偏移索引属于存储设计调整，应单独测查询与重建性能。

不建议为这次缩包重写 Java 核心：本轮 JRE 与 Jar 合计约 78.0 MB，词典与 Electron 才是主要部分。依赖裁剪、旧链清理、词典载体和桌面框架替换的收益与风险应分别评估。

## 候选版本与资料格式

旧产物目录可能混有不同时期的 DMG、ZIP 和后来覆盖的 `.app`；应比对包内版本、Jar、规范摘要和词典清单，不只看相同文件名。

未发布的旧 Core 可能只接受 schema 8，当前源码使用 schema 100。旧应用打开新格式会被拒绝，外层错误可能显示 `BeanCreationException`。不要清库或降级资料来绕过；使用匹配的应用/Core/JRE 整体候选和隔离验收入口。正式发布与验证范围见[版本路线](发布与路线图.md)及[测试与 CI](测试与CI.md)。
